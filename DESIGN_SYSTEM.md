# KELBET — Дизайн-система

Правила для `apps/web`. Документ обязателен к прочтению перед любой правкой UI —
человеком или агентом. Если правило мешает — сначала меняем документ, потом код.

Стек интерфейса: **Vite 8 + React 19 + TypeScript, чистый CSS**.
Tailwind, shadcn/ui, CSS-in-JS и UI-киты в проект **не входят** — см. [Решения](#принятые-решения).

---

## 1. Единственный источник истины

Все токены живут в одном блоке `:root` в начале `src/styles/global.css`.
Других блоков `:root` в проекте быть не должно.

> Исторически их было два — на строке 1 и на строке 5633. Второй молча
> переопределял акцентный цвет и оба шрифта. Именно так дизайн-система и умирает:
> не от плохого вкуса, а от второго `:root`, о котором никто не помнит.

Локальные токены разрешены — но только как scoped-переопределения на корне
подсистемы, как это уже сделано в `.admin-shell`:

```css
.admin-shell {
  --admin-surface: rgba(9, 27, 23, 0.92);
  --admin-line: rgba(148, 177, 168, 0.2);
}
```

Это правильный паттерн: подсистема объявляет свою палитру у себя на корне,
а не рассыпает литералы по 50 правилам.

## 2. Цвет

**Правило: ни одного цветового литерала вне блока `:root`.**

Ни `#58e2bd`, ни `rgba(88, 226, 189, 0.12)` — только `var(--kelbet-accent)`.
Нужен цвет, которого нет в палитре? Значит, нужен новый токен, а не литерал.

| Токен | Назначение |
|---|---|
| `--kelbet-ink` | самый глубокий фон, подложка приложения |
| `--kelbet-forest` | основной фон поверхностей |
| `--kelbet-forest-raised` | приподнятые поверхности, карточки |
| `--kelbet-paper` | основной текст |
| `--kelbet-accent` | акцент: активные состояния, ключевые действия |
| `--kelbet-accent-strong` | акцент под нажатием, границы фокуса |
| `--kelbet-accent-dim` | акцентная заливка низкой интенсивности |
| `--kelbet-sand` / `--kelbet-gold` | тёплый вторичный акцент, премиальные состояния |
| `--kelbet-mist` / `--kelbet-haze` | холодные серо-зелёные: вторичный текст, границы |
| `--kelbet-shade` | глубокая тень, подложки затемнения |
| `--kelbet-line` / `--kelbet-line-cool` | границы, разделители |
| `--kelbet-danger` | деструктивные действия и ошибки |

### Один мятный

Раньше в проекте жили два фирменных мятных: `#58e2bd` и `#3dcfb6`, различающиеся
на ΔE 8.89 — то есть видимо. Второй остался от первой версии палитры и встречался
даже чаще нового: 70 вхождений против 39. Пользователь видел оба на одном экране.

**Канонический акцент — `--kelbet-accent` (#58e2bd).** Выбран не на вкус:
на всех трёх поверхностях приложения он даёт более высокий контраст.

| Фон | `#58e2bd` | `#3dcfb6` |
|---|---|---|
| `--kelbet-ink` | **11.90:1** | 9.86:1 |
| `--kelbet-forest` | **10.91:1** | 9.04:1 |
| `--kelbet-forest-raised` | **9.56:1** | 7.92:1 |

Оба проходили WCAG AA с запасом, так что решение свелось к запасу прочности
и к тому, что #58e2bd — часть более поздней, осознанной палитры.

Слитые дубли: #3dcfb6 → `--kelbet-accent` (67 вхождений), старый песочный
#d8c3a1 → `--kelbet-sand` (ΔE 2.42), #030e0c → `--kelbet-shade` (ΔE 0.45).

Прозрачность задаём через `color-mix`, а не новым rgba-литералом:

```css
/* нет */  background: rgba(88, 226, 189, 0.12);
/* да  */  background: color-mix(in srgb, var(--kelbet-accent) 12%, transparent);
```

**Прогресс:** 356 вхождений сведены к токенам, уникальных литералов стало
**145 вместо 339**. Остаток — длинный хвост из редких одноразовых цветов;
он разбирается по экранам вместе с остальной работой над ними.

**Осторожно с `--tg-theme-*`.** Эти переменные Telegram переписывает в рантайме
через `applyTelegramTheme` в `shared/telegram/webapp.ts` — они меняются под тему
пользователя. Статический литерал, случайно совпавший со значением такого токена,
привязывать к нему нельзя: цвет поедет у пользователей с другой темой.
Для интерфейсных цветов всегда используй статические `--kelbet-*`.

## 3. Типографика

Шрифты грузятся в `index.html` через Google Fonts. Не объявляй в CSS семейство,
которого нет в этом `<link>`.

> Долгое время в токенах стоял `Aptos` — системный шрифт Microsoft. На iOS и
> Android, то есть на всех реальных устройствах Telegram Mini App, его нет.
> Весь интерфейс рендерился системным Noto Sans, а заявленная типографика не
> существовала. Проверяй, что шрифт реально доставляется на устройство.

- `--kelbet-font-display` — **Syne**. Заголовки, крупные числа, акцентные подписи.
- `--kelbet-font-body` — **Manrope**. Весь остальной текст.
- `--kelbet-font-mono` — технические значения, ID, таймкоды.

### Шкала кеглей

Только эти семь значений. Любой `font-size` вне шкалы — ошибка ревью.

| Токен | Размер | Где применяется |
|---|---|---|
| `--kelbet-text-xs` | 11px | подписи, метки, служебный текст |
| `--kelbet-text-sm` | 12px | вторичный текст, мета-информация |
| `--kelbet-text-md` | 13px | основной текст интерфейса |
| `--kelbet-text-lg` | 15px | акцентный текст, заголовки карточек |
| `--kelbet-text-xl` | 18px | заголовки секций |
| `--kelbet-text-2xl` | 22px | заголовок экрана |
| `--kelbet-text-3xl` | 28px | крупные числа, витринные заголовки |

**11px — нижняя граница, жёсткая.** Ниже текст нечитаем на телефоне и это первое,
что выдаёт непрофессиональный интерфейс.

Шкала применена: 393 объявления `font-size` сведены к семи токенам, 121 правило
с кеглем 8–10px поднято до 11px. Литеральных значений ниже 32px в CSS не осталось.

**Исключение — display-типографика.** 26 объявлений с кеглем от 34px и выше, а также
все `clamp()` для витринных заголовков оставлены как есть: это художественные решения
конкретных экранов, а не шкала интерфейса. Новые такие значения добавлять только
осознанно и с `clamp()`, чтобы заголовок не ломал узкие экраны.

## 4. Отступы

Шкала: `--kelbet-space-1..8` → 2, 4, 8, 12, 16, 20, 24, 32px.

Применена к `padding`, `margin`, `gap` и `inset`: **785 значений сведены
к восьми токенам**. Было 34 разных числа, включая 5, 7, 9, 11, 13, 15 и 17px —
разница в пиксель не несёт смысла, а неровный ритм виден сразу.

При округлении равные расстояния разрешались **в меньшую сторону**: кегли уже
выросли на шаге 2, и наращивать вдобавок отступы значило бы раздуть плотные
экраны. Максимальное изменение — 2px.

Оставлены литералами 11 значений больше 32px — это крупные разовые отбивки
секций и позиционирование, а не ритм интерфейса.

## 5. Радиусы

| Токен | Значение | Применение |
|---|---|---|
| `--kelbet-radius-xs` | 4px | теги, мелкие индикаторы |
| `--kelbet-radius-sm` | 10px | поля ввода, кнопки |
| `--kelbet-radius-md` | 16px | карточки |
| `--kelbet-radius-lg` | 24px | модальные окна, крупные панели |
| `--kelbet-radius-pill` | 999px | чипы, аватары, круглые кнопки |

`--kelbet-radius: 18px` — **deprecated**, остаток параллельной шкалы. Схлопывать
на `-md` или `-lg`.

### Срезанный угол — фирменная форма

В проекте было 90 правил с составным радиусом вида `3px N N`: маленький верхний
левый угол при крупных остальных. Это не случайность и не мусор — это узнаваемый
силуэт карточек KELBET, и он сохранён.

```css
/* карточка с фирменным срезом */
border-radius: var(--kelbet-radius-xs) var(--kelbet-radius-md) var(--kelbet-radius-md);
```

Две основные вариации покрывают почти всё: `xs md md` (37 правил) и
`xs sm sm` (34). Размер среза всегда `xs` — раньше он гулял от 1px до 5px без
причины.

Шкала применена: **62 разных значения сведены к 19 формам** на пяти токенах.
`50%` оставлен как есть — это эллипс для аватаров, у него другая семантика.

## 6. Тени и глубина

Глубину показываем поверхностью и границей, а не тенью. Тень — для того, что
физически лежит над контентом: модальные окна, выпадающие меню, липкая навигация.

Изначально это правило звучало как «ровно три ступени». При разборе 47 теней
выяснилось, что оно слишком грубое: `box-shadow` в проекте выполняет **четыре
разные работы**, и сводить их в одну шкалу — значит потерять смысл.

| Роль | Токен | Что это |
|---|---|---|
| Высота | `--kelbet-shadow-sm` / `-md` / `-lg` | объект лежит над контентом |
| Высота вверх | `--kelbet-shadow-up` | липкие нижние панели и шторки |
| Кольцо | `--kelbet-ring-width` | фокус и выделение: `0 0 0 var(--kelbet-ring-width) <цвет>` |
| Маркер | — | `inset 0 -2px var(--kelbet-accent)` и подобное: подчёркивание активного состояния, не глубина |

Ширина кольца одна на весь проект, цвет — по смыслу: акцент для фокуса,
`--kelbet-danger` для ошибки. Раньше кольца были шириной от 1px до 5px наугад.

**Свечения — отдельная история.** 12 правил вида `0 0 Npx <акцент>` это не тень,
а именно свечение, запрещённое разделом 7. Они не тронуты здесь намеренно:
их удаление меняет вид экранов и относится к шагу 6, а не к работе над шкалой.

### Слои

Различай два разных `z-index`.

**Слои приложения** — то, что перекрывает интерфейс целиком: липкие панели,
навигация, оверлеи, модальные окна, тосты. Здесь только токены:

`--kelbet-z-base` (1) · `-sticky` (20) · `-nav` (40) · `-overlay` (60) ·
`-modal` (80) · `-toast` (100)

**Локальный порядок внутри компонента** — бейдж поверх картинки, псевдоэлемент
под контентом. Значения 1, 2, -1 внутри собственного контекста наложения
допустимы: они относительны и не участвуют в общей иерархии.

Раньше слои приложения были расставлены наугад: 15, 20, 25, 50, 80, 120.
Отсюда и берутся баги «модалка под навбаром». Сейчас 7 правил переведены
на токены с сохранением исходного порядка перекрытия.

## 7. Эффекты

Первая версия этого раздела запрещала градиенты, `backdrop-filter` и свечения
списком: «55 linear-gradient, 12 radial-gradient, 14 blur — это и есть вайбкод».
Разбор показал, что правило било мимо цели. Вот что там на самом деле.

### Атмосфера — это замысел, а не мусор

Фон приложения — не «градиент ради градиента»:

```css
body::before {
  opacity: 0.12;
  background-image:
    linear-gradient(90deg, color-mix(in srgb, var(--kelbet-sand) 8%, transparent) 1px, transparent 1px),
    linear-gradient(color-mix(in srgb, var(--kelbet-sand) 5%, transparent) 1px, transparent 1px);
  background-size: 96px 96px;
  mask-image: linear-gradient(to bottom, black, transparent 72%);
}
```

Это сетка в 12% непрозрачности с маской затухания и мягкие радиальные подсветки
по углам. Сдержанно, осмысленно и делает фон живым, не отвлекая. Удалять такое —
не «наведение порядка», а обеднение продукта.

### Что действительно запрещено

- **Свечение как украшение.** Тень акцентным цветом там, где она ничего не
  сообщает о состоянии.
- **Новые значения мимо токенов.** Не «ещё один градиент на карточку», а
  переиспользование существующего приёма.
- **`!important`** в споре со специфичностью — поднимай специфичность честно.
- **Анимации, которые ничего не сообщают** пользователю.
- **Эмодзи вместо иконок** интерфейса.

### Что разрешено и почему

- **Атмосферный фон** — текстура и подсветки на `body`, как выше.
- **Функциональные градиенты** — прогресс, скелетоны загрузки, маски затухания
  у прокручиваемых лент.
- **`backdrop-filter` на липких панелях** — `.bottom-nav`, `.panel`,
  `.create-action`. Полупрозрачная панель над прокручивающимся контентом это
  платформенная идиома iOS и Telegram, а не эффект ради эффекта.
- **Свечение состояния** — через два токена, не наугад:

| Токен | Роль |
|---|---|
| `--kelbet-glow-selected` | выбранный вариант в списке моделей, форматов, рецептов |
| `--kelbet-glow-dot` | индикаторная точка-лампочка |

Раньше выбранное состояние светилось на 12px, 16px и 18px в трёх разных местах —
одинаковое по смыслу, разное по исполнению. Теперь один токен.

Уважение к `prefers-reduced-motion` реализовано глобально — не отменяй локально.

### Когда `!important` уместен

Первая версия документа объявляла все 23 `!important` техдолгом. При разборе
выяснилось, что это неверно: **13 из них — правильные паттерны доступности**.

- `.visually-hidden` — скрытие контента от глаз с сохранением для скринридера.
  `!important` защищает утилиту от случайного переопределения. Это канон.
- блок `prefers-reduced-motion` — глобальное подавление анимаций обязано
  побеждать любые локальные правила, иначе оно бессмысленно.

Настоящий долг — 6 объявлений в `.admin-kicker`, `.admin-inline-error`,
`.video-resolution-field` и `.result-download`. Их нельзя убрать вслепую: нужно
понять, с какой специфичностью они спорят. Это работа с запущенным приложением.

## 8. Иконки

Единственный источник — `src/shared/ui/Icon.tsx`: сетка 24px, `stroke-width` 1.6,
`currentColor`, `aria-hidden`.

```tsx
import { Icon } from "@/shared/ui/Icon";
<Icon name="wallet" width={20} height={20} />
```

**Инлайновые `<svg>` в страницах запрещены.** Сейчас их ноль на 6596 строк —
это хорошее состояние, его нужно удержать.

Нужна новая иконка — добавь путь в `Icon.tsx` на той же сетке и с той же
толщиной обводки. Не подключай иконочные библиотеки: набор уже консистентен,
а зависимость принесёт чужую сетку и чужую толщину линий.

Эмодзи в роли иконок интерфейса не использовать — они рендерятся по-разному
на разных платформах и ломают вертикальный ритм.

## 9. Разметка

Классы семантические, по владельцу: `home-task-card`, `admin-issue-list`,
`video-mode-switch`. Утилитарные классы (`flex`, `mt-4`, `text-sm`) не используем —
в проекте их ноль, так и оставляем.

Инлайновые стили — только для действительно динамических значений
(вычисленная ширина прогресса). Сейчас их 5 на весь проект.

Цвета в TSX не хардкодим никогда. Сейчас — ноль хардкод-цветов, это норма.

## Принятые решения

**Почему не shadcn/ui.** shadcn требует Tailwind, которого в проекте нет.
Установка означала бы переписать 8091 строку CSS и 12 страниц ради слоя разметки,
который уже чистый: ноль инлайновых SVG, ноль хардкод-цветов, семантичные классы.
Проблема проекта не в отсутствии компонентной библиотеки, а в том, что токен-слой
существует и его обходят 340 раз. Библиотека это не лечит.

**Почему не иконочная библиотека.** `Icon.tsx` уже даёт консистентный набор
на единой сетке. Замена добавила бы зависимость без выигрыша в качестве.

**Что чиним вместо этого.** Токен-слой и дисциплину его использования.
Это те же правила, что стоят за интерфейсами Linear и Vercel: там нет секретного
UI-кита, там есть небольшой набор токенов, от которого никто не отступает.
